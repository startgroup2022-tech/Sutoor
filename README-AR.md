# سطور — تطبيق Flutter (المرحلة الأولى)

تطبيق Flutter مبدئي مرتبط بالـAPI الفعلي لمشروع سطور على `https://sutoor.it.com/api/v1`، ويستخدم شعار الموقع وألوانه المستخرجة من `assets/css/style.css`.

## الشاشات المبرمجة
- الرئيسية: الشعار والبانر والتصنيفات والكتب من قاعدة بيانات الموقع.
- الكتب: تصفح وبحث محلي ضمن الكتب المرجعة من API، وتفاصيل الكتاب.
- الباقات: عرض الباقات وطرق الدفع المحددة من لوحة الإدارة، وإنشاء طلب اشتراك `pending`، وفتح رابط واتساب إذا أعاده الخادم.
- حساب العميل: إنشاء حساب وتسجيل دخول وخروج وطلبات العميل والاشتراكات؛ حفظ رمز الدخول في تخزين الجهاز الآمن.
- فحص صلاحية الكتاب: استدعاء `/books/{id}/access` وعرض الحالة؛ **لا يوجد قارئ PDF محمي أو تنزيل فعلي بعد** لأن API لا توفر مساراً محمياً لتدفق الملف.

## إنشاء مشروع Flutter قابل للبناء
هذه الحزمة تحتوي كود Dart وملفات الأصول والإعدادات، لكنها **ليست ملف APK أو مشروع Xcode كامل مولّداً**: بيئة التسليم لا تحتوي Flutter SDK.

1. ثبّت Flutter stable وAndroid Studio (ولـiOS تحتاج macOS وXcode).
2. داخل مجلد الحزمة: `flutter create --platforms android,ios --org com.sutoor .`
3. ثم `flutter pub get`.
4. لتشغيل التطبيق: `flutter run --dart-define=SUTOOR_API_URL=https://sutoor.it.com/api/v1`.
5. لبناء Android: `flutter build apk --release` أو `flutter build appbundle --release` بعد إعداد توقيع النشر.
6. iOS: إعداد bundle id والتوقيع وApp Store Connect حسب حساب المطوّر.

## خادم الموقع — متطلبات قبل الإطلاق
- API تدعم: GET /books, /categories, /plans, /payment-methods, /me, /me/orders, /me/subscriptions, /books/{id}/access؛ POST /auth/login, /auth/register, /auth/logout, /me/orders.
- يرجى التحقق من تشغيل جميع هذه المسارات فعلياً على cPanel واختبار API عبر HTTPS قبل اعتماد النسخة.
- حالياً تسجيل الدخول بكلمة المرور دون آلية استرجاع كلمة مرور/تأكيد بريد. يلزم استكمالهما.
- يلزم مسار قراءة/تحميل آمن قائم على ترخيص كل كتاب وباقة، والحد من إساءة استخدام رموز الدخول، وإدارة الجلسات والأجهزة.
- استيراد غلاف الكتاب: لا تُستخدم إلا المسارات المحلية `assets/img/covers/` الآتية من الخادم.
- كل الأسعار والإعدادات والطلبات تُقرأ من API وليس من بيانات ثابتة داخل التطبيق.
- التسويق أو الشراء عبر واتساب من تطبيقات المتاجر قد يخضع لسياسات دفع المنتجات الرقمية؛ يلزم التحقق من سياسات App Store وGoogle Play قبل الإطلاق.

## الحماية
لا يحتوي المشروع كلمات مرور MySQL أو أسرار الخادم. لا تتصل تطبيقات الجوال بـMySQL مباشرة. الموافقة على الدفع اليدوي تتم من لوحة الإدارة فقط ولا يمنح إنشاء الطلب اشتراكاً فعالاً.
